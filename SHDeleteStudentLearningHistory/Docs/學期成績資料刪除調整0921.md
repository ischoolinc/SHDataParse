## 3. student_learning_history 查詢條件

查詢 Method：`GetLearningHistoryData`

條件包含：

* `school_year`＝畫面學年度
* `semester`＝畫面學期
* `name`＝成績類別解析後名稱
* `serial_no`＝成績類別解析後代碼
* `ref_student_id IN (...)`＝目前選取且可轉成數字的學生系統編號（Distinct）

回傳欄位：`id`, `ref_student_id`, `school_year`, `semester`, `name`, `serial_no`  
排序：`ref_student_id`, `id`

僅查目前所選學生，不查全部學生；查詢結果保留 `id` 供後續 DELETE 使用。

## 4. ScoreType 轉換成 name / serial_no

新增 `TryParseScoreType`，解析**最後一組括號**：

| 畫面顯示 | name | serial_no |
|---------|------|-----------|
| 學期成績(4.2) | 學期成績 | 4.2 |
| 學期成績(預檢)(41.2) | 學期成績(預檢) | 41.2 |

DB 查詢不直接用完整顯示字串比對 `name`。

## 5. 學生 ID 查詢方式

* 來源：constructor 傳入並複製保存的 `_StudentIDs`
* 查詢前以 `long.TryParse` 過濾合法數字 ID，再 `Distinct`
* 沒有合法學生 ID：提示後結束，不執行 SQL
* `IN` 子句只拼接數字 ID，避免字串拼接注入

## 6. 確認畫面統計方式

查詢有資料後才顯示確認：

* **總學生數**：查詢結果 `ref_student_id` Distinct 數（非 `_StudentIDs.Count`）
* **總筆數**：查詢到的 `student_learning_history` 筆數

確認訊息包含學年度、學期、成績類別、總學生數、總筆數。  
按鈕為確定／取消，預設焦點在**取消**（`MessageBoxDefaultButton.Button2`）。  
取消則直接 return，不 DELETE、不寫成功 Log、不關閉主畫面。

## 7. DELETE 使用 id 的設計

Method：`DeleteLearningHistory(List<long> historyIDs)`

* 使用確認前查詢取得的 `id`（Distinct）
* SQL：

```sql
DELETE FROM student_learning_history
WHERE id IN (...)
RETURNING id;
```

* 透過 `QueryHelper.Select` 執行並取回實際刪除的 id
* **不**以 school_year / semester / name / serial_no / ref_student_id 作為 DELETE 條件

## 8. Log 記錄內容

成功：

* `ApplicationLog.Log("刪除學習歷程資料", "刪除", ...)`
* 內容含：學年度、學期、畫面成績類別、name、serial_no、總學生數、查詢總筆數、實際刪除筆數、學生系統編號、刪除的 id
* 若查詢總筆數 ≠ 實際刪除筆數，額外寫入警告

失敗（Exception）：

* `ApplicationLog.Log("刪除學習歷程資料", "刪除失敗", Exception.ToString())`
* 畫面顯示錯誤訊息，不讓 Exception 直接中斷程式

## 9. 資料重新整理方式

DELETE 成功並寫 Log 後：

```csharp
FISCA.Features.Invoke("StudentSyncAllBackground");
```

重新整理包在獨立 try/catch；Refresh 失敗**不**視為刪除失敗，也不再執行 DELETE。

## 10. Exception 處理

* `btnDel_Click` 外層 try / catch / finally
* catch：寫失敗 Log + MsgBox 顯示錯誤訊息
* finally：一定 `btnDel.Enabled = true`
* 流程開始立即 `btnDel.Enabled = false`，避免連點重複刪除
